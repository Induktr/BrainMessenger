# Инструкция по Требованиям Проекта BrainMessenger (MVP)

## 1. Введение: MVP как Фундамент Цифрового АКТИВА

**Название проекта:** BrainMessenger

**Описание:** Этот документ определяет требования к **Минимально Жизнеспособному Продукту (MVP)** BrainMessenger. MVP — это **прагматичный** (Принцип 12) шаг, направленный на создание **базового, но качественного и работающего Фундамента** (Принцип 8, 3) для будущего **цифрового АКТИВА** (Принцип 10). MVP сфокусирован на предоставлении ключевой **ценности** (Принцип 2) — базового, но надежного обмена сообщениями и файлами, а также основных системных функций.

**Цель проекта (MVP):** Разработать и запустить MVP BrainMessenger, демонстрирующий **высокое качество исполнения** (Принцип 3) и закладывающий **прочную техническую и архитектурную ОСНОВУ** (Принцип 8, 9) для будущей масштабируемости. MVP должен включать базовые функции обмена сообщениями, файлами, создания каналов/групп, управления темами и основными настройками аккаунта, соответствующие минимальным требованиям безопасности и удобства использования.

Этот документ описывает требования для MVP проекта, разделенные на категории, а также анализ текущего состояния реализации, основанный на текущих задачах, видео трекере и выполненных работах.

**Обозначения:**
*   ✅ - Требование полностью выполнено (в рамках MVP)
*   ▶️ - Требование частично выполнено / В процессе активной реализации (в рамках MVP)
*   [ ] - Требование запланировано, но реализация еще не начата (в рамках MVP)
*   ❌ - Вне рамок MVP (перенесено на последующие этапы Дорожной карты)

### 4.2. Что Требует Доработки (▶️/[ ] в рамках MVP)

*   **Ядро Переписки:** Полная реализация отправки и получения текстовых сообщений (нужен WebSocket + интеграция backend/frontend).
*   **Работа с Файлами:** Реализация скачивания файлов.
*   **Каналы и Группы:** Доведение до конца функционала создания, подписки и чтения (включая отображение в UI).
*   **Настройки Аккаунта:** Доработка формы профиля (удаление аккаунта, базовые настройки безопасности/уведомлений).
*   **Базовое Тестирование:** Написание самих модульных тестов (Jest). Настройка и написание базовых E2E тестов (Cypress/Detox).
*   **Базовая Поддержка:** Реализация формы обратной связи в приложении (собирает информацию для email).
*   **Базовый Мониторинг и Логирование:** Настройка сбора метрик (Prometheus), визуализации (Grafana) и алертов для ключевых показателей MVP.

### 4.3. Возникшие Трудности (Потенциальные в рамках MVP): Наши Затыки

*   **Реализация Каналов/Групп:** Может быть сложнее, чем кажется, из-за логики доступа и уведомлений (публичные vs приватные).
*   **Реализация Скачивания Файлов из R2:** Может потребовать настройки подписанных URL или специфической логики на Frontend/Backend.
*   **WebSocket (Real-time):** Реализация надежной доставки сообщений в реальном времени, управление состоянием онлайн/офлайн.
*   **Интеграция Компонентов Стека:** Согласование работы всех частей (NestJS, Prisma, Redis, Kafka, Cloudflare R2, Frontend) в единой системе.
*   **Тестирование E2E:** Настройка и поддержка E2E тестов на разных платформах (Web, RN) может быть трудоемкой.

### 4.4. Рекомендации и Качественные Практики (в рамках MVP): Наш План Действий (Кайдзен)

Чтобы успешно завершить MVP и обеспечить его качество, продолжаем применять наши принципы и лучшие практики:

*   **Фокус на Качестве (Принцип 3):** Не торопиться в ущерб качеству кода, особенно в критически важных частях (переписка, безопасность, работа с файлами).
*   **Системный Подход (Принцип 9):** Убедиться, что все компоненты (Backend, Frontend, DB, R2, Redis, Kafka) правильно интегрированы и взаимодействуют.
*   **Увеличивать Покрытие Тестами (Принцип 3, 9):** Активно писать модульные тесты (Jest) и настроить/писать базовые E2E тесты (Cypress/Detox) для ключевых сценариев MVP. Интегрировать тесты в CI/CD.
*   **Непрерывная Интеграция и Доставка (CI/CD):** Использовать CI/CD (например, Vercel для Web, GitHub Actions для Backend/RN) для автоматической сборки, тестирования и деплоя изменений. Это ускоряет и надежность процесса.
*   **Мониторинг и Логирование (Принцип 9, 5):** Активировать базовый мониторинг (Prometheus/Grafana) и логирование/отслеживание ошибок (ELK/Sentry) для MVP. Использовать эти данные для выявления проблем и узких мест.
*   **Код-ревью:** Регулярно проводить ревью кода, обмениваясь знаниями и находя потенциальные дефекты.
*   **Поддерживать Документацию:** Актуализировать техническую документацию и комментарии в коде по мере завершения MVP функционала. Это часть **системы знаний** (Принцип 1).

## 5. Технологический Стек Проекта (Фундамент Актива)

*   **Язык:** TypeScript (Frontend & Backend) - **Качество, Системность**
*   **Frontend:** React, Next.js (Web), React Native (Mobile/Desktop) - **Ценность (Кроссплатформа), Системность (Фреймворки)**
*   **Backend:** Node.js, NestJS - **Производительность, Системность (Фреймворк)**
*   **База Данных:** PostgreSQL (Neon) - **Надежность, Масштабируемость, Прагматизм**
*   **ORM:** Prisma - **Качество (Типобезопасность, Безопасность SQLi), Системность**
*   **API:** GraphQL - **Эффективность, Гибкость**
*   **Real-time:** WebSockets - **Ценность (Общение в реальном времени), Производительность**
*   **Кэширование:** Redis - **Производительность, Системность**
*   **Очереди:** Kafka - **Надежность, Масштабируемость, Системность (Асинхронность)**
*   **Хранилище Файлов:** Cloudflare R2 - **Прагматизм, Масштабируемость, АКТИВ**
*   **Уведомления:** Firebase - **Прагматизм, Ценность**
*   **Email/2FA:** Gmail API - **Прагматизм, Безопасность**
*   **Платежи:** Stripe, Cryptomus (Вне MVP) - **АКТИВ (Монетизация), Прагматизм**
*   **Тестирование:** Jest (MVP), Cypress, k6, Playwright, OWASP ZAP/Burp Suite (планируется) - **Качество, Системность**
*   **Развертывание:** Vercel (Web), Docker/Kubernetes (Backend, Workers) - **Системность, Масштабируемость**
*   **Мониторинг:** Prometheus, Grafana, Sentry (планируется) - **Видимость, Кайдзен**
