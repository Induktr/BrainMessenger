# Документация UI BrainMessenger (Интерфейс, Создающий Ценность)

### 1. Общая Информация: UI как Лицо Системы

**Название проекта:** BrainMessenger

**Описание:** Этот документ описывает пользовательский интерфейс (UI) BrainMessenger. UI — это **лицо нашей системы** (Принцип 9), через которое пользователи взаимодействуют с приложением и воспринимают его **ценность** (Принцип 2). Мы стремимся создать UI, который будет **интуитивно понятным, эффективным и доступным**, отражая принципы **качества > количества** (Принцип 3) и **упрощения сложного**.

**Цель:** Предоставить четкое описание основных экранов, принципов навигации, используемых элементов UI, функциональных требований к интерфейсу и типовых пользовательских сценариев. Это помогает обеспечить **единообразие** (Принцип 7) и **качество** (Принцип 3) пользовательского опыта на всех платформах.

**Принципы, отраженные в UI:**

*   **Создание Ценности (Принцип 2):** UI сфокусирован на предоставлении ключевых функций (общение, файлы, звонки) максимально удобным способом.
*   **Качество > Количество (Принцип 3):** Предпочтение отдается чистому дизайну с четкой иерархией элементов, а не перегруженному интерфейсу.
*   **Система и Оптимизация (Принцип 9):** UI построен на модульной системе компонентов и следует четким правилам выравнивания и сетки (см. DocDesign). Навигация и рабочие процессы оптимизированы.
*   **Долгосрочное Мышление (Принцип 8):** Дизайн учитывает возможность добавления нового функционала в будущем, не нарушая общую структуру.
*   **Здоровье как Фундамент (Принцип 5):** Уделяется внимание доступности (WCAG), использованию темной темы, настройкам анимаций для снижения нагрузки на пользователя.
*   **Прагматизм и Реализм (Принцип 12):** Дизайн учитывает технические ограничения и возможности кроссплатформенной разработки.

### 2. Основные Экраны: Путь Пользователя по Системе

Основные экраны представляют собой ключевые точки взаимодействия пользователя с системой BrainMessenger.

1.  **Welcome Screen:**
    *   **Цель:** Представить BrainMessenger, его основные преимущества и **ценность** (Принцип 2). Онбординг новых пользователей.
    *   **Элементы:** Заголовок, краткое описание, слайдер с информацией (преимущества, функции, обновления), кнопки "Sign Up" (Регистрация) и "Log In" (Вход).
    *   **Связь:** Использует градиент и шрифты из DocDesign для привлечения внимания. Наличие слайдера с описанием функционала — часть стратегии **создания ценности** (Принцип 2).
2.  **Экраны Аутентификации (Регистрация / Вход / Подтверждение кода / Сброс пароля):**
    *   **Цель:** Предоставить безопасный и понятный процесс доступа к системе.
    *   **Элементы:** Поля ввода (Email, Пароль, Имя, Код), кнопки действия, ссылки ("Забыли пароль?").
    *   **Требования:** Строгая валидация ввода (см. Функциональные требования), четкие сообщения об ошибках. Связано с **безопасностью** (Принцип 5) и **качеством** (Принцип 3).
3.  **Главный Экран (Список Чатов):**
    *   **Цель:** Обеспечить быстрый доступ ко всем текущим диалогам пользователя.
    *   **Элементы:** Список чатов (личные, групповые, каналы) с краткой информацией (название, аватар, последнее сообщение, время, счетчик непрочитанных), строка поиска, кнопка создания нового чата ("+"), доступ к главному меню ("бургер" или аватар).
    *   **Организация:** Чаты сортируются по времени последнего сообщения для **эффективности** (Принцип 9).
    *   **Действия:** Открытие чата (кликом), архивирование/удаление (свайпом или контекстным меню).
4.  **Экран Чата:**
    *   **Цель:** Обеспечить удобный обмен сообщениями и файлами.
    *   **Элементы:** Шапка чата (название, аватар, кнопки звонка/видеозвонка/информации), область сообщений, поле ввода сообщения, кнопки прикрепления файла/отправки/голосового сообщения.
    *   **Сообщения:** Отображение текстовых сообщений, изображений, файлов. Индикаторы статуса (отправлено, доставлено, прочитано).
    *   **Настройки чата:** Доступны через шапку чата (изменение темы, шрифта - см. раздел 13).
5.  **Экран Контактов:**
    *   **Цель:** Управление списком контактов и поиск новых пользователей.
    *   **Элементы:** Список контактов, строка поиска, кнопка добавления нового контакта.
6.  **Настройки Профиля:**
    *   **Цель:** Позволить пользователю управлять своей личной информацией и настройками аккаунта.
    *   **Элементы:** Поля для редактирования имени, email, пароля, загрузки аватара, опции безопасности (2FA), кнопка удаления аккаунта. Связано с **ответственностью** (Принцип 6) пользователя за свои данные.
7.  **Настройки Приложения:**
    *   **Цель:** Настроить общее поведение приложения под предпочтения пользователя.
    *   **Элементы:** Разделы настроек (Уведомления, Внешний вид/Тема, Язык, Батарея и Анимации, Хранилище данных). Предоставление выбора повышает **ценность** (Принцип 2).
8.  **Экран Premium:**
    *   **Цель:** Объяснить преимущества Premium-подписки и предоставить возможность ее оформления.
    *   **Элементы:** Описание функций Premium (например, глитч-эффект, нейронные связи в UI - см. DocDesign), информация о тарифах, кнопка "Подписаться", ссылка на историю платежей. Связано с **созданием ценности** (Принцип 2) и **монетизацией Актива** (Принцип 10).
9.  **Экраны Звонков (История / Экран звонка / Конференция):**
    *   **Цель:** Обеспечить функциональность аудио- и видеосвязи.
    *   **Элементы:** Список прошлых звонков, интерфейс активного звонка (видеопоток, кнопки Mute/Unmute, видео вкл/выкл, завершить звонок, переключить камеру), интерфейс конференции.
10. **Экран Файлов и Медиа:**
    *   **Цель:** Предоставить удобный доступ ко всем файлам, которыми пользователь обменивался в чатах.
    *   **Элементы:** Список файлов (с превью для медиа), фильтрация по типу (фото, видео, документы), поиск. Организовано **системно** (Принцип 9).
11. **Экран Архив Чатов:**
    *   **Цель:** Скрыть менее актуальные чаты из основного списка, сохраняя к ним доступ.
    *   **Элементы:** Список архивированных чатов, возможность восстановления. Часть **системы организации** (Принцип 9).
12. **Настройки Языка:**
    *   **Цель:** Позволить пользователю выбрать язык интерфейса.
    *   **Элементы:** Список доступных языков. Смена языка происходит **мгновенно** или после быстрого перезапуска, что повышает **ценность** (Принцип 2) и **доступность** (Принцип 5) приложения. Поддерживается RTL (справа налево) для некоторых языков (см. DocLocIn).
13. **Настройки Батареи и Анимации:**
    *   **Цель:** Позволить пользователю контролировать потребление ресурсов устройством.
    *   **Элементы:** Переключатель для полного отключения анимаций, возможно, регулировка отдельных эффектов. Это **прагматичное** (Принцип 12) решение, учитывающее **здоровье** устройства (Принцип 5).
14. **Настройки Чата (Кастомизация):**
    *   **Цель:** Позволить пользователю персонализировать внешний вид отдельных чатов.
    *   **Элементы:** Опции выбора цвета фона чата, выбора шрифта для сообщений. Это добавляет **ценность** (Принцип 2) за счет кастомизации.

### 3. Принципы Навигации: Понятный Путь по Системе

Навигация спроектирована так, чтобы быть **интуитивно понятной** (Принцип 2) и следовать **системным правилам** (Принцип 9).

*   **Последовательность:** Экраны аутентификации и регистрации проходят последовательно.
*   **Главное Меню:** Обеспечивает доступ к основным разделам приложения (Чаты, Контакты, Звонки, Настройки, Архив).
*   **Внутри Чата:** Доступ к информации о чате/пользователе и настройкам чата обычно через шапку.
*   **Возврат:** Четкий способ вернуться на предыдущий экран (кнопка "Назад").
*   **Welcome Screen:** Слайдер для пошагового знакомства с функциями.

### 4. Структура Интерфейса: Построение на Системе Компонентов (Принцип 9)

UI построен на **модульной системе компонентов**, что обеспечивает **единообразие, скорость разработки и поддерживаемость** (Принцип 9).

*   **Элементы UI:**
    *   **Текстовые блоки (Text):** Используются для отображения текста. Следуют типографической шкале из DocDesign.
    *   **Кнопки (Button):** Интерактивные элементы для выполнения действий. Имеют четкие состояния (нормальное, нажатое, отключенное - см. DocDesign для стилей).
    *   **Поля ввода (Input):** Для ввода текста, паролей, чисел. Включают плейсхолдеры, метки, индикаторы ошибок.
    *   **Иконки (Icon):** Используются для навигации, действий (отправить, звонить) и декоративных целей. Единый набор и стиль (см. DocDesign). Могут иметь анимации.
    *   **Изображения (Image):** Отображение аватаров, изображений в чатах. Используется оптимизированная загрузка.
    *   **Слайдер (Carousel):** Используется на Welcome Screen.
    *   **Переключатели (Toggle):** Для настроек типа вкл/выкл.
*   **Выравнивание и Сетка:** UI строится на основе **системы сетки 8px** (см. DocDesign).
    *   **Вертикальный поток:** Элементы на экранах располагаются сверху вниз с четкими вертикальными отступами.
    *   **Горизонтальное выравнивание:** Элементы выравниваются по левому или правому краю контейнеров (с учетом RTL).
    *   **Отступы (Padding/Margin):** Используются значения из шкалы, кратной 8px, для создания гармоничного пространства.
*   **Адаптивный Дизайн:** UI адаптируется под разные размеры экрана и ориентацию устройства для обеспечения **ценности** (Принцип 2) на любом устройстве.

### 5. Функциональные Требования к UI: Детализация Взаимодействия

*   **Ввод Пароля:** Должен быть маскированным (`*` или `•`). Должна быть опция показать/скрыть пароль. Минимальная длина 8 символов, требование наличия цифры и спецсимвола — валидация на клиенте и сервере.
*   **Ввод Email:** Проверка формата (`user@domain.com`).
*   **Ввод Кода Подтверждения:** Поле ввода для 8-значного кода. Автоматическое переключение на следующее поле при вводе цифры (удобство - Принцип 2). Проверка корректности кода при отправке на сервер.
*   **Поиск:** Фильтрация списков (чатов, контактов) по мере ввода запроса (отзывчивость - Принцип 9).
*   **Управление Профилем:** Поля для редактирования, кнопка сохранения, валидация нового email/пароля.
*   **Оформление Подписки:** Перенаправление на страницу оплаты Stripe (см. DocInt).
*   **Переключение Слайдов:** Слайдер на Welcome Screen должен плавно переключаться по свайпу или клику на стрелки/индикаторы.
*   **Изменение Языка:** Выбор языка из списка. UI должен обновиться мгновенно или после запроса на перезапуск (см. DocLocIn).
*   **Настройка Анимаций:** Переключатель должен включать/отключать основные анимации.
*   **Кастомизация Чата:** Изменение цветов/шрифтов должно применяться к конкретному чату.

**Обработка ошибок в UI:**
*   **Валидация ввода:** При некорректном вводе (например, неверный формат email, слишком короткий пароль) под полем ввода появляется **ясное визуальное уведомление** с описанием проблемы (Принцип 3, 14). Кнопка действия может быть отключена до исправления.
*   **Ошибки сети/API:** При ошибках взаимодействия с Backend (например, "Неверный логин/пароль", "Пользователь не найден", "Ошибка сети") в верхней части экрана появляется **неблокирующее уведомление (Snackbar/Toast)** с описанием ошибки, полученной из API (см. DocSpec, локализация - см. DocLocIn).

### 6. Пользовательские Сценарии: Примеры Взаимодействия с Системой

Типовые пути пользователей, демонстрирующие работу системы с точки зрения конечного пользователя.

1.  **Регистрация нового пользователя:**
    *   Пользователь открывает приложение → Нажимает "Sign Up" → Вводит пароль (валидация) → Нажимает "Next" → Вводит имя → Нажимает "Next" → Вводит email (валидация) → Нажимает "Sign Up" → Получает email с кодом → Возвращается в приложение → Вводит код → Нажимает "Confirm" → Успешный вход на Главный экран.
2.  **Вход существующего пользователя:**
    *   Пользователь открывает приложение → Нажимает "Log In" → Вводит email и пароль → Нажимает "Log In" → (Если 2FA включена: Получает email с кодом → Вводит код → Нажимает "Confirm") → Успешный вход на Главный экран. При ошибке логина/пароля - уведомление.
3.  **Отправка текстового сообщения:**
    *   Пользователь на Главном экране → Открывает чат (клик) → Вводит текст в поле ввода → Нажимает "Отправить" → Сообщение появляется в чате.
4.  **Отправка файла:**
    *   В открытом чате → Пользователь нажимает "скрепку" → Выбирает тип файла (фото) → Выбирает файл из галереи → (Возможно, предпросмотр) → Нажимает "Отправить" → В чате появляется индикатор загрузки/файл с превью.
5.  **Поиск чата:**
    *   На Главном экране → Пользователь вводит запрос в строку поиска → Список чатов фильтруется в реальном времени.
6.  **Изменение темы оформления:**
    *   На Главном экране → Пользователь открывает Главное меню → Переходит в "Настройки" → "Внешний вид" → Выбирает "Dark" → UI мгновенно переключается на темную тему.

### 7. Примечания: Фокус на Пользовательском Опыте

*   **Тестирование:** Важно тестировать UI на реальных устройствах с разными размерами экрана, разрешениями и настройками доступности (размер шрифта, инверсия цветов) для обеспечения **качества** (Принцип 3) и **доступности** (Принцип 5).
*   **Обратная Связь:** UI будет развиваться на основе **обратной связи** (Принцип 14) от пользователей и анализа их поведения.
*   **Последовательность:** UI на всех платформах (Web, Mobile, Desktop) должен быть максимально **последовательным** (Принцип 7), чтобы пользователь, освоив одну версию, мог легко использовать другие.
*   **Анимации:** Анимации используются для улучшения восприятия, но могут быть отключены. Они должны быть **оптимизированными** (Принцип 9) и не вызывать дискомфорт.
*   **Кастомизация:** Предоставление опций кастомизации (тема, шрифт) повышает **ценность** (Принцип 2) приложения для пользователя.
